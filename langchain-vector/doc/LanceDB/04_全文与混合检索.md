# 04 全文与混合检索

## 为什么需要关键词？

语义向量可以覆盖意译，但对精确标识符、型号、条款编号不一定可靠。全文检索（FTS）对文本建倒排索引，用 BM25 为关键词匹配打分；混合检索把关键词与向量的排名融合。它们不是同一分数的简单相加。

## 可运行的本地演示

依照 [01 的安装步骤](01_本地入门与向量检索.md)安装 `@lancedb/lancedb`。将下列代码保存为 `hybrid.ts`，运行 `npx tsx hybrid.ts`：

```typescript
import * as lancedb from "@lancedb/lancedb";

const db = await lancedb.connect("./lancedb-demo");
const table = await db.createTable("hybrid_docs", [
    { id: "policy", text: "Policy R001 allows hotel reimbursement", vector: [1.0, 0.0] },
    { id: "travel", text: "Travel rules for hotels and trains", vector: [0.8, 0.2] },
    { id: "leave", text: "Annual leave approval procedure", vector: [0.0, 1.0] },
], { mode: "overwrite" });

await table.createIndex("text", { config: lancedb.Index.fts() });
const fts = await table.query().fullTextSearch("R001", { columns: "text" }).limit(3).toArray();
console.log("FTS:", fts.map((row) => [row.id, row._score]));

const vector = await table.search([0.9, 0.1]).limit(3).toArray();
console.log("向量:", vector.map((row) => [row.id, row._distance]));

const hybrid = await table.query()
    .fullTextSearch("R001", { columns: "text" })
    .nearestTo([0.9, 0.1])
    .limit(3)
    .toArray();
console.log("混合:", hybrid.map((row) => [row.id, row._relevance_score]));
```

TS SDK 使用 `createIndex` 创建 FTS 索引；查询同时提供文本和向量时构成混合检索。

`_score` 是 FTS 的匹配分数，`_distance` 是向量距离，`_relevance_score` 是融合后的相关性分数；三者不能拿同一个阈值比较。混合结果可以包含只在向量分支命中的记录，例如本例的 `leave`，不能将其视为关键词命中。示例的二维数值是合成向量；真实文本搜索应对存储文本和问题使用兼容的 embedding 模型生成向量。未提供 embedding 定义时，混合查询显式传 `.nearestTo(...)` 和 `.fullTextSearch(...)`，不能只传字符串就期望自动得到语义向量。默认融合使用 RRF（倒数排名融合）；可以用 `.rerank(...)` 指定其他重排器，但复杂模型重排器还需要相应依赖或服务。

## 中文与增量数据

默认分词适合空格分隔的文本，不能假设它会正确切分无空格中文。混合语言可评估 ICU 分词；无空格中文应先核对所用 SDK 的分词选项和模型文件要求，验证命中后再决定索引配置。建索引后继续 `await table.add(...)`，新记录可以通过未索引片段的回退扫描找到，但查询可能变慢；定期 `await table.optimize()` 更新索引。`.fastSearch()` 只检索索引内数据，可能漏掉新记录。
