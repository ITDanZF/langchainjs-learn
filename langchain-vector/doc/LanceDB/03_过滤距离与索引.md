# 03 过滤、距离与索引

## 先过滤还是先找近邻？

沿用 [01 的本地数据库](01_本地入门与向量检索.md) 中的 `intro_docs` 表。以下完整片段在第一课运行后执行：

```typescript
import * as lancedb from "@lancedb/lancedb";

const db = await lancedb.connect("./lancedb-demo");
const table = await db.openTable("intro_docs");
const queryVector = [0.9, 0.1];
const filtered = await table.query().nearestTo(queryVector)
    .where("category = 'travel'").limit(2).toArray();
console.log(filtered.map((row) => [row.id, row._distance]));

const postfiltered = await table.query().nearestTo(queryVector)
    .where("category = 'leave'").postfilter().limit(2).toArray();
console.log("后过滤:", postfiltered);
```

默认 `where` 是预过滤：只在符合条件的记录中排序。`.postfilter()` 则先取最相近候选再过滤，可能不足 `limit` 条甚至为空；权限、租户或版本约束应使用预过滤，不应依赖后过滤来确保结果范围。生产中拼接用户输入到 SQL 条件之前必须进行严格校验，不能把任意输入直接当谓词执行。

## 距离类型

无索引时默认使用 L2（欧氏距离）；可以用 `.distanceType("cosine")` 按方向比较。两者得到的 `_distance` 数值含义不同，不能混用阈值。建向量索引时应指定与使用场景一致的度量，并保持查询与索引一致。`_distance` 是几何距离，不是模型回答的可信概率。

## 什么情况下需要索引？

三条记录直接扫描更直观。数据增长后可以建 ANN（近似近邻）索引以改善延迟，但需要实测召回与资源开销；不要拿这三条数据作为索引收益的基准。向量索引示例（**仅示意，先在较大的真实向量表上执行**）：

```typescript
await table.createIndex("vector", {
    config: lancedb.Index.ivfPq({ distanceType: "cosine" }),
});
console.log(await table.listIndices());
```

`table` 应是一个足量真实数据的表；不是上面三行的教学表。索引训练对行数、向量维度和分区参数有要求。ANN 可能漏掉精确最近邻，部分压缩索引返回的 `_distance` 也可能是近似距离。比较质量时以 `.bypassVectorIndex()` 的精确扫描结果作为参考：

```typescript
const truth = await table.query().nearestTo(queryVector).bypassVectorIndex().limit(10).toArray();
const ann = await table.query().nearestTo(queryVector).limit(10).toArray();
```

这里 `queryVector` 必须与真实表向量维度相同，片段是检索评估思路，不是独立运行脚本。新增记录通常仍能被查询的未索引数据回退扫描查到；`await table.optimize()` 将新增记录纳入已有索引。不要随意启用 `.fastSearch()`，它可能跳过尚未索引的新记录。经常用于 `where` 的列可以建立标量索引，如 `await table.createIndex("category", { config: lancedb.Index.bitmap() })`。
