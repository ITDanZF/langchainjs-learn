# 01 配置与首次向量化

`text-embedding-v4` 是阿里云百炼的文本向量模型，不是 OpenAI 自家的模型。这里用 LangChain.js 的 `OpenAIEmbeddings` 调用百炼 **OpenAI 兼容**接口；`baseURL` 决定请求发送到哪里，`model` 决定请求哪个模型。不要把聊天模型 `qwen-plus` 用作 embedding 模型。

## 准备

使用 Node.js 20+，在独立练习目录执行：

```powershell
mkdir embedding-v4-demo
cd embedding-v4-demo
npm init -y
npm pkg set type=module
npm install @langchain/openai @langchain/core
npm install -D tsx typescript @types/node
```

先在百炼控制台获取与所选地域相符的 API Key。仅在当前 PowerShell 会话设置密钥，不要写在代码、文档或 Git 中：

```powershell
$env:DASHSCOPE_API_KEY = [System.Net.NetworkCredential]::new(
  "", (Read-Host "DashScope API Key" -AsSecureString)
).Password
```

以下示例默认使用北京公共云兼容接口 `https://dashscope.aliyuncs.com/compatible-mode/v1`。如果你的业务空间使用专属 API Host 或其他地域，在当前会话设置 `$env:DASHSCOPE_BASE_URL = "控制台提供的兼容模式URL"`（例如业务空间 Host 的 `/compatible-mode/v1`），并使用对应地域的 API Key；不要误填 DashScope 原生接口的 `/api/v1`。

## 首次调用

保存为 `first.ts`，运行 `npx tsx first.ts`（需要有效密钥和网络；请求可能计费）：

```typescript
import { OpenAIEmbeddings } from "@langchain/openai";

const apiKey = process.env.DASHSCOPE_API_KEY;
if (!apiKey) throw new Error("请先设置 DASHSCOPE_API_KEY");

const embeddings = new OpenAIEmbeddings({
  apiKey,
  model: "text-embedding-v4",
  batchSize: 10,
  configuration: {
    baseURL: process.env.DASHSCOPE_BASE_URL ?? "https://dashscope.aliyuncs.com/compatible-mode/v1",
  },
});

const queryVector = await embeddings.embedQuery("如何报销上海出差住宿？");
console.log("查询向量维度:", queryVector.length); // 默认 1024
console.log("前 5 个值:", queryVector.slice(0, 5));

const texts = ["上海差旅住宿标准", "年假申请流程"];
const documentVectors = await embeddings.embedDocuments(texts);
console.log("文档数:", documentVectors.length);
console.log("文档向量维度:", documentVectors.map((vector) => vector.length));
```

`embedQuery` 用于问题，`embedDocuments` 用于文档；两者必须使用同一模型、维度与兼容配置。不要把这些浮点值当成可读解释，它们的用途是比较文本在向量空间的距离。

如果遇到 401，先检查密钥和地域是否匹配；404 检查兼容模式 URL 与模型名；429 检查限流与重试频率。不要在报错日志里输出密钥。
